# Credential-free workload adapter

`resources` explicitly selects `deployments`, `replicasets`, `pods`, and/or core-v1 `events`. The prepared configuration selects all four; omission retains the original Pod-only adapter for compatibility. All reads are namespace scoped. `config/kubernetes-role.example.yaml` is a source-owner review template, not installed permissions. No Secrets, specs, annotations, commands, env values, pods/log or exec subresource is stored/read.

The collector performs one bounded LIST page or short WATCH per tick, rotating resources. Cursor state includes configuration scope (endpoint, approved IPs, namespace, credential reference), opaque resourceVersion, page token hashes, UID-keyed sanitized inventory and phase. Transient watch failures reconnect at the saved version; expiration relists and exposes a gap. Configuration-scope changes also relist. List pages must retain the same list resourceVersion; repeated tokens, page limits, inventory/byte limits and malformed objects cannot yield complete coverage.

Defaults/bounds: page size <=200, max pages <=100, configured inventory <=500 objects per resource (default200), watch <=200 records, <=100 emitted transitions per tick, cursor JSON <=500KB, observation summary <=60KB. A transition budget overrun leaves the checkpoint unchanged and reports `workload_transition_budget_exceeded`; narrow scope or review budgets rather than discarding transitions to display green. A source that exceeds its retention of watch history may later require relist with a gap. Budgets do not promise lossless eternal history.

Cursor CAS/fencing and observation/evidence writes share one transaction after HTTP. No transaction waits for HTTP. Restart after an uncommitted result rereads the same position. On initial/relist inventory no deployment/incident is fabricated. New observed generation is evidence of change, not proof of rollout success. Pod -> ReplicaSet -> Deployment ownership uses actual UID references; missing/multiple/cyclic owners remain unresolved. Name reuse never joins old and new UIDs.

Restart deltas and fresh OOMKilled termination identities produce evidence; an old termination reason does not create repeated OOMs. Event UID/count increments preserve multiplicity; repeated resource versions do not increment counts. Final increments in known deleted objects are retained. Summary has explicit coverage, resource inventory counts, owner chains, changes and historical gap flag. No change is unknown, not healthy.

A configured `service_id` binds notices to an explicitly approved **namespace-level/shared target** covered by that source. Do not map a multi-service namespace source to one individual service and claim all its Pods belong to it. Fine-grained per-service workload selectors/topology require separate reviewed mappings. Unmapped sources retain observations without inventing service/environment impact. Workload observations and reported pipeline deployments remain distinct.

Live RBAC/server compatibility, actual namespace inventory, workload identity, clock skew, sampling and budgets must be verified later. Locally tested with synthetic HTTP contracts and real PostgreSQL. The adapter is ordinary code and has no AI dependency.
